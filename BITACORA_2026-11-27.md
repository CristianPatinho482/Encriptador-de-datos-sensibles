## 1. Corrección del error de ejecución en VS Code (Code Runner)

**Problema reportado:** al ejecutar `app_anonimizador_universal.py` con el botón Run Code,
aparecía: *"El sistema no puede encontrar la ruta especificada"* (exit code 1).

**Diagnóstico:**
- La extensión **Code Runner v0.12.2** ejecutaba literalmente `[Running] /usr/bin/env python3 "archivo"`.
- Causa raíz identificada: la opción `code-runner.respectShebang` (activada **por defecto**)
  interpreta la primera línea del archivo; los scripts contenían el *shebang* Unix
  `#!/usr/bin/env python3`, que no existe en Windows.

**Acciones realizadas:**
1. Eliminación del *shebang* de los 3 archivos Python
   (`app_anonimizador_universal.py`, `test_anonimizador_universal.py`, `generar_datos_demo.py`).
2. Verificación: compilación limpia y suite unitaria **31/31 OK**.
3. Commit y publicación a GitHub: `6a2fb8e` — *"Quitar shebang Unix que rompía Code Runner en Windows"*.
4. Verificación posterior (a solicitud): confirmación de que `origin/main` en GitHub
   apunta al commit corregido y que la versión del repositorio ya no contiene el shebang.

## 4. Documento de Especificación Formal v2.0 (ecuaciones nativas de Word)

**Objetivo:** completar el documento de especificación matemática con métodos formales
y convertir las expresiones a ecuaciones legibles y editables.

**Acciones realizadas:**
1. Análisis del documento original (`especificacion-formal-anonimizador-universal.docx`):
   se identificó notación plana (Consolas), un bloque de código corrompido y secciones
   formales incompletas.
2. Desarrollo del generador `generar_especificacion_formal.py` con un mini-constructor
   de ecuaciones **OMML** (Office Math Markup Language): subíndices, superíndices,
   sub/superíndices combinados, centrado y numeración de ecuaciones.
3. Generación de `especificacion-formal-anonimizador-universal_v2.docx` con:
   - **32 ecuaciones nativas de Word** (editables en el editor de ecuaciones):
     dominios (D_PII, C, K ∈ {0,1}^256, K_c, Vault, D^⊥), transformaciones de ambos modos
     criptográficos, **teorema de biyectividad con boceto de demostración**, determinismo,
     cero-fuga por construcción, inyectividad, precondiciones P1–P3, postcondiciones Q1–Q3,
     tabla de invariantes I1–I5, huella de verificación SHA-256 de multiconjunto,
     pipeline de 3 fases, regla formal de detección PII.
   - 5 tablas y 8 secciones, incluidas referencias normativas (Ley 1581, GDPR,
     NIST SP 800-38A, FIPS 198-1, Hoare 1969, ISO/IEC 27001).
4. Verificación estructural del documento (conteo de ecuaciones y sub/superíndices) y
   copia en la carpeta Descargas junto al documento original.
5. Commit: `56d9c09`; `*.docx` añadido a `.gitignore` (el documento se regenera
   con `python generar_especificacion_formal.py`).
